# Data Flow — Ingestion & ML Pipeline

This is the offline path that turns raw FPL data into a deployable XGBoost model. It runs as three manual steps today (no scheduler is wired up yet); the diagram shows the full chain so you can see how each artifact feeds the next.

```mermaid
flowchart LR
    subgraph external [External]
        fplApi(["FPL Official API<br/>bootstrap-static / element-summary"])
    end

    subgraph rawStore [Source of truth]
        sqlite[("SQLite<br/>fpl_intel.db")]
    end

    subgraph featureStep ["Step 1 — Feature engineering<br/>(ml/features.py)"]
        loadDb["Load players + fixtures<br/>+ teams from SQLite"]
        engineer["Engineer 28 features<br/>per-90 rates · ownership · form ·<br/>fixture difficulty · injury flag · position one-hot"]
        writeCsv["Write data/fpl_features.csv<br/>(one row per active player)"]
    end

    subgraph trainStep ["Step 2 — Training<br/>(ml/train.py)"]
        readCsv["Read fpl_features.csv"]
        split["Train/test split<br/>80% / 20%"]
        impute["SimpleImputer (median)<br/>StandardScaler"]
        fit["Fit XGBoost + RandomForest<br/>5-fold CV comparison"]
        eval["Evaluate: MAE, RMSE, R²<br/>Feature importance"]
        writeModel["Pickle bundle<br/>{model, imputer, feature_cols, metrics}"]
        writeReport["Write reports + 9 visualizations"]
    end

    subgraph artifacts [Artifacts]
        csv[("data/<br/>fpl_features.csv")]
        xgb[("models/<br/>fpl_xgboost.pkl")]
        rf[("models/<br/>fpl_randomforest.pkl")]
        report[("ml/reports/<br/>fpl_model_report.json<br/>fpl_feature_importance.csv<br/>fpl_players_enriched.csv")]
        viz[("ml/imgs/<br/>viz1-9_*.png")]
    end

    subgraph inferStep ["Step 3 — Inference<br/>(ml/predict.py)"]
        loadBundle["Load pickle bundle"]
        loadInputCsv["Read input CSV"]
        runPredict["Transform + predict"]
        printTable["Print prediction table to stdout"]
    end

    fplApi -- "manual / scripted load" --> sqlite
    sqlite --> loadDb --> engineer --> writeCsv --> csv
    csv --> readCsv --> split --> impute --> fit --> eval
    eval --> writeModel --> xgb
    eval --> writeModel --> rf
    eval --> writeReport --> report
    eval --> writeReport --> viz

    xgb --> loadBundle --> runPredict
    csv --> loadInputCsv --> runPredict --> printTable
```

## What each step produces

| Step | Script | Reads | Writes |
|------|--------|-------|--------|
| 1. Features | `ml/features.py` | `fpl_intel.db` | `data/fpl_features.csv` |
| 2. Training | `ml/train.py` | `data/fpl_features.csv` | `models/*.pkl`, `ml/reports/*`, `ml/imgs/*` |
| 3. Inference | `ml/predict.py <csv>` | `models/fpl_xgboost.pkl` + input CSV | stdout table |

## The pickle bundle format

`predict.py` expects every `models/*.pkl` to be a **dict bundle**, not a bare estimator:

```python
{
    "model":        XGBRegressor(...),
    "imputer":      SimpleImputer(strategy="median"),
    "feature_cols": [...],          # 28 column names, exact order
    "model_name":   "XGBoost",
    "metrics":      {"MAE": 4.89, "RMSE": 7.11, "R2": 0.974}
}
```

This bundle pattern is what makes inference re-runnable from any CSV that was generated by the same `features.py` — the column order and imputer strategy travel with the model.

## Notes & gaps

- The arrow from FPL API → SQLite is **manual today**. The empty file `pipeline/fpl_api.py` is the placeholder for an automated loader.
- `pipeline/scheduler.py` is also empty — there is no cron/Airflow wiring. Re-training happens when a maintainer runs the three commands.
- `ml/reports/fpl_players_enriched.csv` is also fed into the RAG indexing pipeline (see `rag-indexing-pipeline.md`) so the vector store reflects the latest model predictions.
